# Tidings docs site

Astro Starlight powered docs at `docs.gettidings.com` (eventually). Runs locally on port 4321.

## Develop

From the repo root:

```bash
make dev-docs
# → http://localhost:4321/
```

Or directly:

```bash
cd docs-site
pnpm dev
```

The `predev` and `prebuild` scripts sync content from `/docs/` into `src/content/docs/` and copy `/openapi.json` into `public/`. Both run automatically; force a re-sync with `pnpm sync`.

## Where content lives

| Surface | Source | Sync |
| ------- | ------ | ---- |
| Welcome, Quickstart, Docker self-host, Guides hub, API page | `src/content/docs/*.mdx` (hand-written here) | n/a |
| Architecture, AWS deploy, Email setup, Notifications | `/docs/{ARCHITECTURE,guides/*}.md` (canonical) | `scripts/sync-content.mjs` |
| API reference at `/api` | `/openapi.json` (drift-checked in CI) | `scripts/copy-openapi.mjs` |
| Brand tokens | `/frontend/src/index.css` (canonical) | `scripts/sync-tokens.mjs` → `src/styles/tidings-tokens/` (imported by `src/styles/tidings.css`; synced so the tokens' bare `tailwindcss` imports resolve from docs-site deps — the deploy build never installs frontend deps) |

To add a new ported page, edit the source markdown in `/docs/` and add an entry to the `pages` array in `scripts/sync-content.mjs`. To add a hand-written page, drop a new `.mdx` file in `src/content/docs/` with `title` and `description` frontmatter, then list it in `astro.config.mjs` under `sidebar`.

## Brand

The bridge file `src/styles/starlight-overrides.css` maps Tidings tokens onto Starlight's `--sl-*` variables. To adjust theming, edit that file — never hand-tune Starlight defaults.

A small inline script (in `astro.config.mjs` `head`) mirrors Starlight's `[data-theme='dark']` to a `.dark` class on `<html>` so Tidings' own dark-mode tokens activate.

### Fonts

Source Serif 4, Inter and JetBrains Mono are **self-hosted**, not loaded from Google. They are declared in the top-level `fonts` block in `astro.config.mjs` (Astro's Fonts API), downloaded at build time, and emitted to `/_astro/fonts/` with content-hashed filenames. `src/overrides/Head.astro` renders the `<Font>` tags that emit the `@font-face` rules — without it the generated `--font-*` variables resolve to nothing. `starlight-overrides.css` maps those generated variables back onto the Tidings `--font-serif` / `--font-sans` / `--font-mono` tokens (the `tidings-tokens/` copies are generated by `scripts/sync-tokens.mjs`, so they can't be edited).

Two things this buys, both of which are easy to undo by accident:

- **No layout shift.** Same-origin and preloaded, the font lands before first paint, so the wordmark paints once at its final width instead of reflowing 104.52px → 111.58px. Reverting to a `<link>` puts the font behind a third-party DNS + TLS + CSS round-trip and brings the reflow back. Astro also derives a metrics-matched fallback (`size-adjust` / `ascent-override` / …) that cuts the reflow to ~1px if a swap does happen on a slow link — though that face is `src: local("Times New Roman")`, so it is inert on Linux boxes without the MS core fonts.
- **No third-party request.** Nothing is fetched from `fonts.googleapis.com` / `fonts.gstatic.com` at runtime, which is the behaviour a privacy-focused project should have on its own docs.

Source Serif 4 pins its `opsz` axis to `8..60` via `options.experimental.variableAxis`. Dropping it makes Astro fetch the `wght` axis only, which pins optical sizing to its default and renders visibly wider glyphs. Only `normal` styles are requested: the hero's rust italic has always been synthesized, and pulling a real italic would change how it renders.

`public/_headers` marks `/_astro/*` `immutable`; without it Cloudflare Pages serves those hashed assets with a 4-hour `must-revalidate`.

## Deploy

A separate Cloudflare Pages project via git-integration (no deploy workflow in this repo):

- Root directory: `docs-site`
- Build command: `pnpm install --frozen-lockfile && pnpm build`
- Build output directory: `dist`
- Environment variables: `PNPM_VERSION=10`, `NODE_VERSION=22` (Astro 6 requires Node ≥ 22.12)
- Build watch paths (include): `docs-site/*`, `docs/*`, `openapi.json`,
  `frontend/src/index.css`, `frontend/src/styles/themes.css` — everything the
  prebuild sync reads. Watching only `docs-site/*` would skip rebuilds on real
  content changes, since most pages sync in from `/docs/`.
- Custom domain: `docs.gettidings.com`

The `prebuild` sync reads `../docs/` and `../openapi.json` — Pages clones the full repo, so this works as long as no "limit clone to root directory" option is enabled. Maintainer runbook and rationale (why git-integration over a wrangler action): `docs/specs/00_open-source-migration/2026-07-05-web-surfaces-launch/README.md` §6 / L9 — that folder is git-excluded (local-only), read it by path.
